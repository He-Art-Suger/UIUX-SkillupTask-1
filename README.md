# UI/UXスキルアップ課題①：OpsBoard UI改善

## 課題の目的

Next.js / React / TypeScript を使い、既存のたたき台UIを改善しながら、以下の経験を積むことを目的とします。

- 複数ページを持つプロダクトの情報設計
- ユーザーが迷いにくいUI設計
- 一覧、詳細、可視化ページの改善
- コンポーネント単位のテスト
- Playwrightによる基本的な画面遷移テスト

## 想定プロダクト

**OpsBoard** は、カスタマーサクセス担当者が顧客対応タスクを管理する小規模業務アプリです。

現在はバックエンドとの接続が最低限できている状態を想定しています。このテンプレートでは `src/lib/mockApi.ts` がバックエンドAPIの代替です。

## 現在の状態

最低限、以下は動作します。

- タスク一覧ページ `/`
- タスク詳細ページ `/tasks/[id]`
- インサイトページ `/insights`
- mock APIからのタスク取得
- コンポーネントテストの雛形
- E2Eテストの雛形

ただし、UI/UXには意図的に改善余地を残しています。

## 5時間課題の進め方

### 1. 既存UIの観察・課題整理：30分

以下の観点で、現在のUIの問題を5個以上書き出してください。

- 一覧で優先的に見るべき情報が分かるか
- タスクの状態や緊急度が直感的に伝わるか
- 詳細画面で次のアクションが明確か
- インサイトページが意思決定に役立つか
- スマホ表示で使いやすいか
- アクセシビリティ上の問題がないか

提出物例：

```md
## UI/UX課題メモ
1. 優先度が文字だけで、緊急性が伝わりにくい
2. 検索UIがあるが実際には機能していない
3. 詳細画面の保存ボタンが何を保存するのか不明確
```

### 2. 改善方針の設計：45分

以下を簡単に決めてください。

- 主なユーザー：例）カスタマーサクセス担当者
- ユーザーの目的：例）今日対応すべき顧客課題を素早く見つける
- 最重要画面：例）タスク一覧
- 改善方針：例）「優先度」「期限」「状態」を視覚的に判断できるようにする

余裕があれば簡単なワイヤーフレームを紙やFigmaで作成してください。

### 3. タスク一覧ページの改善：90分

必須改善：

- 検索機能を実装する
- ステータスによる絞り込みを実装する
- 優先度・期限・状態が視覚的に分かるUIにする
- 空状態を実装する
- スマホ表示を改善する

発展改善：

- 並び替えを追加する
- 期限が近いタスクを強調する
- タスクカードをより再利用しやすい構造にする

### 4. タスク詳細ページの改善：60分

必須改善：

- 「背景」「ユーザーの声」「次のアクション」を分かりやすく分離する
- 保存ボタンの意味を明確にする
- 戻る導線を改善する
- 重要情報をファーストビューで把握できるようにする

発展改善：

- 改善メモ入力欄を追加する
- 保存時の成功メッセージを表示する
- API更新を想定した関数を `mockApi.ts` に追加する

### 5. インサイトページの改善：45分

必須改善：

- 重要指標の見せ方を改善する
- 「このページを見て何を判断すべきか」が分かる説明を追加する
- 高優先度タスクや未完了タスクへの導線を追加する

発展改善：

- 簡単なグラフ風UIをCSSで作る
- ステータス別の割合を表示する
- 次に見るべきタスクを推薦する

### 6. テスト追加：45分

最低限、以下を追加してください。

- 検索結果が絞り込まれることのテスト
- ステータス絞り込みのテスト
- タスク詳細への遷移テスト
- 空状態表示のテスト

テスト対象はすべて網羅する必要はありません。UI改善に対して「壊れていないことを確認する最低限のテスト」を意識してください。

### 7. 振り返り：15分

最後に以下を書いてください。

```md
## 振り返り
- 改善前の主な問題:
- 改善したこと:
- ユーザーにとって良くなった点:
- テストで保証したこと:
- 次に改善したいこと:
```

## 完了条件

以下を満たせば課題完了です。

- `npm run dev` で画面が表示できる
- 一覧、詳細、インサイトの3ページが確認できる
- 一覧ページで検索または絞り込みが動く
- UI改善の意図をREADMEまたは別ファイルに記載している
- 主要なコンポーネントまたは画面のテストを1つ以上追加している

## 起動方法

```bash
npm install
npm run dev
```

テスト実行：

```bash
npm test
npm run test:e2e
```

Playwrightを初回利用する場合：

```bash
npx playwright install
```

## 評価観点

- 見た目だけでなく、ユーザーの判断が速くなる改善になっているか
- UIの状態が明確か：空状態、保存成功、絞り込み結果なしなど
- コンポーネント分割が自然か
- アクセシビリティを意識しているか
- テストが改善内容に対応しているか

## 追加チャレンジ

時間が余った場合は以下に取り組んでください。

- `localStorage` を使って改善メモを保持する
- タスクのステータス変更UIを作る
- 期限切れタスクを分かりやすく表示する
- キーボード操作だけで主要導線を操作できるか確認する
- Storybookを導入し、TaskCardの状態別表示を確認する
